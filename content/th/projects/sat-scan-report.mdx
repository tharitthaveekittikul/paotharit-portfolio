## ปัญหา

ทุกครั้งที่ SCB Tech X จะปล่อย release ซอฟต์แวร์ต้องผ่านด่านตรวจสอบด้านความปลอดภัยก่อนที่ SCB สำนักงานใหญ่จะอนุมัติ Jenkins pipeline รัน scanner 3 ตัวอยู่แล้ว ได้แก่ Blackduck, Coverity และ Aquasec แต่ละตัวสร้าง output ในรูปแบบ PDF, CSV และ HTML ปัญหาคือขั้นตอนถัดไป — ต้องมีคนนั่งคัดลอกข้อมูลจากไฟล์เหล่านั้นมาใส่ spreadsheet ด้วยมือ จัดระดับความรุนแรงแต่ละรายการ แล้วจัดรูปแบบเป็น Excel เพียงไฟล์เดียวให้ทีม HQ ดำเนินการ ด้วยหลายโปรเจกต์และรอบ release ที่ถี่ ขั้นตอนนี้ช้า เกิดข้อผิดพลาดง่าย และทำให้กระบวนการอนุมัติติดขัด

## Pipeline การสแกน

การสแกนความปลอดภัยรันอัตโนมัติเป็นส่วนหนึ่งของ Jenkins deployment pipeline ทุก build เมื่อสิ้นสุด scanner 3 ตัวจะสร้างไฟล์รายงานของตัวเอง:

| Scanner   | ตรวจสอบอะไร                                | รูปแบบ output |
| --------- | ------------------------------------------ | ------------- |
| Blackduck | ช่องโหว่ใน open-source dependencies (CVEs) | PDF / CSV     |
| Coverity  | Static analysis — จุดอ่อนในโค้ด (CWEs)     | HTML          |
| Aquasec   | ช่องโหว่ใน container image (CVEs)          | PDF           |

ไฟล์เหล่านี้คือวัตถุดิบ และ SAT Scan Report จะรับช่วงต่อจากนั้น

## การจัดระดับความรุนแรง

แต่ละรายการถูกจัดระดับเป็นหนึ่งใน 4 ระดับ: **Critical**, **High**, **Medium** หรือ **Low** ทีมใช้ข้อมูลนี้ตัดสินใจว่าช่องโหว่ไหนต้องแก้ก่อน release จะได้รับอนุมัติ, ยอมรับได้โดยมี compensation control ที่บันทึกไว้ หรือเลื่อนไปได้ column remark และ compensation control แก้ไขได้โดยตรงในตาราง — วิศวกรกรอกระหว่างการ review ไม่ต้องทำใน spreadsheet แยก

## สร้าง Excel และการอนุมัติ HQ

เมื่อทีม review ช่องโหว่ทุกรายการจากทุก scanner tab แล้ว กด "Generate Excel" จะ export การ review ทั้งหมดเป็นไฟล์ XLSX ไฟล์นั้นคือสิ่งที่ส่งต่อ — senior ตรวจสอบก่อน แล้วจึงส่งไปยังทีมความปลอดภัยของ SCB สำนักงานใหญ่เพื่ออนุมัติขั้นสุดท้าย

## สิ่งที่ได้เรียนรู้

นี่คือโปรเจกต์ internship แรกที่มีข้อจำกัดเชิง enterprise จริงๆ — ผู้ใช้ภายในองค์กร, ขั้นตอนการอนุมัติที่เป็นทางการ, และรายงานที่มีผลกระทบด้าน compliance โดยตรง ส่วนที่น่าสนใจที่สุดคือ layer การ parse ไฟล์ แต่ละ scanner มีรูปแบบและโครงสร้าง output ต่างกัน ดังนั้น logic การดึงข้อมูลต้องรองรับหลาย layout โดยไม่มี schema กลาง การสร้างให้ทำงานได้อย่างน่าเชื่อถือและไม่มีข้อมูลหลุดโดยไม่รู้ตัว ต้องใช้ความระมัดระวังมากกว่าการทำ UI เสียอีก
