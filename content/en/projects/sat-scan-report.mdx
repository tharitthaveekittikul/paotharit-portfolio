## The Problem

Every software release at SCB Tech X had to pass a security gate before deployment could be signed off by SCB headquarters. Jenkins pipelines already ran three scanner tools — Blackduck, Coverity, and Aquasec — and each produced its own output in PDF, CSV, and HTML formats. The problem was what happened next: someone had to manually sift through all those files, copy rows into a spreadsheet, classify each finding by severity, and format everything into a single Excel report the HQ team could act on. With multiple projects and frequent release cycles, that manual step was slow, error-prone, and blocked the approval process.

## The Pipeline

The security scan runs automatically as part of every Jenkins deployment pipeline. At the end of the build, three scan tools each produce their own report files:

| Scanner | What it checks | Output format |
|---------|---------------|---------------|
| Blackduck | Open-source dependency vulnerabilities (CVEs) | PDF / CSV |
| Coverity | Static analysis — code weaknesses (CWEs) | HTML |
| Aquasec | Container image vulnerabilities (CVEs) | PDF |

Those files are the raw material. SAT Scan Report picks up from there.

## How It Works

Engineers log in (email/password or Microsoft SSO), select a project and release version, then upload the raw scanner output files. The app parses each file — extracting CVE IDs, CWE IDs, library names, versions, severity scores — and populates a structured table automatically. No copy-pasting.

## Severity Triage

Each finding is classified into one of four severity levels: **Critical**, **High**, **Medium**, or **Low**. The team uses this to decide whether a vulnerability must be fixed before the release is approved, can be accepted with a documented compensation control, or can be deferred. The remark and compensation control columns are editable directly in the table — the engineer fills them in as part of the review, not separately in a spreadsheet.

## Excel Generation and HQ Approval

Once the team has reviewed all findings across all three scanner tabs, clicking "Generate Excel" exports the entire review to an XLSX file. That file is the deliverable — the senior reviews it first, then it goes to the SCB headquarters security team for final sign-off.

## What I Learned

This was my first internship project with real enterprise constraints — internal users, a formal approval chain, and reports that had direct compliance implications. The most interesting part was the file parsing layer: each scanner had a different output format and structure, so the extraction logic had to handle multiple layouts without a unified schema. Building that reliably, and making sure nothing got silently dropped, required more care than the UI work did.
