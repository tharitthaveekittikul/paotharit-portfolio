## The Problem

SCB debenture holders — stakeholders who had invested in SCB-issued bonds — had no digital way to access the coupon and privilege benefits tied to their holdings. The bank wanted to deliver those benefits through SCB Easy App, the bank's primary mobile platform, and fulfil the coupons through Primo, a third-party coupon provider running its own user platform. The challenge was connecting three moving parts that were never designed to talk to each other: the app interface, the SCB backend, and Primo's AWS-based system.

## System Architecture

Three services make up the system:

- **React web app** — embedded inside SCB Easy App via WebView. Stakeholders access the program without leaving the app; from their perspective it is a native screen.
- **Node.js Express API** — handles business logic, session management, and communicates with Primo's APIs to fetch and redeem coupons based on each user's tier.
- **Spring Boot cron job** — runs on a schedule to migrate debenture holders from SCB's Azure environment into Primo's AWS-based platform, segmented by tier level.

## User Migration: Azure to AWS

Primo runs on AWS, but SCB's user data lives in Azure. To give each debenture holder access to their tier-appropriate coupons on Primo, their accounts had to be migrated across cloud environments and kept in sync as new holders joined.

The Spring Boot cron job handles this automatically: it reads debenture holder records from SCB's Azure environment, segments them by tier, and provisions the corresponding accounts on Primo's AWS platform. Running on a schedule, new holders are onboarded without manual intervention.

## Batch Schedule Cron Job

Beyond user migration, a daily batch schedule handles two-way data exchange between the Business Unit and Primo.

The Business Unit pushes an `Active_User.xlsx` file to Azure Blob Storage every 6 months when a new active user list is available. The batch job reads this file, processes it, and exports user reference IDs to Amazon S3 for Primo to consume. Primo uses those IDs to generate `Cusref.xlsx` — the customer reference file that drives coupon eligibility. A second cron job runs the other direction: it exports `Coupon_Merchandise.xlsx` from the system back to Azure Blob Storage so the Business Unit receives the latest merchandise coupon data.

## What I Learned

I bootstrapped all three services from scratch — choosing the libraries, setting up the project structure, and writing the initial code across the React app, the Express API, and the Spring Boot job. The two mid-level developers on the team had stronger backend backgrounds, so I led on the frontend architecture and coordinated across both layers.

Working at the boundary between three separate systems (SCB, Primo, and the WebView integration) meant every design decision had to account for constraints I didn't always control. Cross-cloud user migration was the most technically demanding part: reliably syncing identity data between Azure and AWS without losing records or creating duplicates required more careful design than any single-service feature I had built before.
